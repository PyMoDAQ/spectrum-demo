# PyMoDAQ spectrum demo: what an ontology layer brings to PyMoDAQ data

A small, self-contained example. Two labs record the absorption spectrum of the same molecule
with different habits (raw counts versus transmittance in percent, wavelength in nm versus
photon energy in eV, different channel names). We show that:

1. **without annotations**, each lab's analysis script fails on the other lab's file, once
   with a crash and once silently with wrong numbers; the usual fix is a hand-written
   configuration per lab;
2. **with annotations** (five IRIs per dataset, stored in PyMoDAQ's existing
   `extra_attributes` and saved in the HDF5 file), one script analyses both files with no
   configuration, explains what it did, and refuses to guess when information is missing;
3. the same annotations give a JSON-LD description of each file, and one SPARQL query can be
   asked to both labs at once.

Start with the notebook: [`notebooks/spectrum_ontology_demo.ipynb`](notebooks/spectrum_ontology_demo.ipynb)
(saved with its outputs, so it can be read without running it).

## Install and run

```bash
git clone <this repo> && cd <this repo>
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -e ".[notebook,test]"
python scripts/make_datasets.py      # (re)creates data/*.h5
jupyter lab notebooks/spectrum_ontology_demo.ipynb
pytest
```

Install with `-e` (editable): the code reads the ontology files from `ontology/` in the
repository. Requires Python ≥ 3.10 and `pymodaq_data` ≥ 5.3 (only the data layer of PyMoDAQ,
no Qt needed). Tested with pymodaq_data 5.3.10, Python 3.13, Linux.

## Contents

| Path | What it is |
|---|---|
| `notebooks/spectrum_ontology_demo.ipynb` | The demo, before / after, step by step |
| `ontology/spectro.ttl` | The small vocabulary of the demo (9 classes, 4 properties): measurement, spectrum, sample / reference / dark spectrum, transmittance and absorbance spectrum, spectral axis. Aligned on SOSA, PROV-O, QUDT, CHMO, PaNET |
| `ontology/external_excerpt.ttl` | The QUDT and CHMO terms used (labels, definitions, unit conversion factors), copied so that the demo runs offline. Generated by `scripts/build_external_excerpt.py` |

## The annotations

Each PyMoDAQ `DataWithAxes` gets five extra attributes:

| Attribute | Meaning | Example (Lab B) |
|---|---|---|
| `semantic_iri` | what the dataset is | `spectro:TransmittanceSpectrum` |
| `quantity_kind` | quantity of the values (QUDT) | `quantitykind:Transmittance` |
| `unit_iri` | unit of the values (QUDT) | `unit:PERCENT` |
| `axis_quantity_kind` | quantity of the spectral axis (QUDT) | `quantitykind:Energy` |
| `axis_unit_iri` | unit of the spectral axis (QUDT) | `unit:EV` |

The axis annotations sit on the data object because PyMoDAQ `Axis` objects have no extra
attributes.

## Status and limits

* Draft vocabulary, not reviewed by spectroscopists. The namespace
  `https://w3id.org/pymodaq/spectro#` is provisional (not reserved on w3id.org).
* QUDT has no "decadic absorbance" quantity kind; `quantitykind:TransmittanceDensity`
  (defined as −lg τ) is used.
* Data are simulated. Lab A uses the `MockSpectrograph` of Bernhard Lang's
  [PyMoDAQ extension tutorial](https://github.com/bernhardlang/pymodaq_plugins_tutorial_extension) (MIT).
